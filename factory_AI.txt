# Resumo do Projeto — AI Factory

## 🎯 Objetivo Central

Construir um **sistema local de engenharia de software assistida por IA** que transforma uma ideia humana em um projeto funcional, passando por especificação, arquitetura, código, testes e correções — **com supervisão humana nos momentos críticos**.

> **Princípio fundamental:** A IA propõe. A Factory controla. O teste valida. O humano decide.

---

## 🧠 O Que a Factory É (e o Que Não É)

| ✅ É | ❌ Não É |
|------|----------|
| Orquestrador de desenvolvimento | Agente autônomo irrestrito |
| Sistema com Zero Trust na LLM | IA que programa sozinha |
| Plataforma com auditoria completa | "Caixa preta" que gera código |
| Ferramenta com Human Gate | Sistema que toma decisões sozinho |
| Memória de decisões e erros | Chat que esquece o contexto |

---

## 🏗️ Arquitetura Conceitual

```
IDEIA HUMANA
     ↓
DIALOGUE LLM ← (faz perguntas, identifica lacunas)
     ↓
ESPECIFICAÇÃO ← (validada pelo humano)
     ↓
PLANNER ← (gera task graph)
     ↓
PLAN VALIDATOR ← (verifica consistência)
     ↓
ORCHESTRATOR ← (controla fluxo e estados)
     ↓
MODEL MANAGER ← (seleciona modelo por tarefa)
     ↓
AGENTE (Qwen/Mistral) ← (executa via ferramentas controladas)
     ↓
TESTER ← (pytest, ruff, mypy)
     ↓
┌──────────┴──────────┐
│                     │
PASS                 FAIL
│                     │
↓                     ↓
COMMIT              ORCHESTRATOR
│                     ↓
↓                  DIAGNÓSTICO
NEXT TASK              ↓
                   HUMANO (aprova correção)
                       ↓
                   CORREÇÃO → TESTE
```

## 🔐 Princípios de Segurança

### Zero Trust para LLM
> *"A palavra da IA não valida o trabalho da IA."*

Toda saída é classificada como:
- **VERIFIED**: Existe evidência (teste passou)
- **UNVERIFIED**: Afirmação sem validação
- **UNKNOWN**: Informação insuficiente

**Regra:** UNVERIFIED/UNKNOWN **nunca** viram FACT/DECISION/ACTION sem aprovação.

### Falha Não É Autorização
> *"Uma falha interrompe a execução. Uma nova tentativa só ocorre após autorização explícita."*

### Três Níveis de Risco
- **Baixo** (criar arquivo, rodar teste) → Automático
- **Médio** (adicionar dependência, alterar DB) → Registro/Confirmação
- **Alto** (apagar dados, git push, deploy) → Aprovação obrigatória

| Componente | Função |

| **Planner** | Requisitos → Task Graph |

| **Model Manager** | Seleciona e gerencia modelos |

| **Tester** | Validação determinística |

## ⚠️ O Que a Factory NÃO Faz

- ❌ Não é IA autônoma irrestrita
- ❌ Não modifica o SO livremente (sem `sudo`, `apt`, `rm -rf`)
- ❌ Não executa código sem controle
- ❌ Não toma decisões importantes silenciosamente
- ❌ Não constrói projeto inteiro de uma vez
- ❌ Não depende da memória da conversa (estado está no projeto)
- ❌ Não usa LLM para tarefas determinísticas (hash, JSON, parsing)
- ❌ Não esconde erros (erro é informação)

---

## 📜 As Duas Regras de Ouro

> **1. A IA pode propor. A Factory pode executar. O teste pode validar. Mas decisões de alto impacto permanecem sob controle humano.**

> **2. Toda decisão importante deve deixar uma trilha que permita entender, meses depois, por que o sistema chegou àquele resultado.**

---

## 🎯 Métrica de Sucesso

A Factory não é medida por "funcionar", mas por:
- **É usada regularmente?**
- **Reduz o tempo de desenvolvimento?**
- **Reduz erros?**
- **É confiável o suficiente para ser delegada?**

---

**Em uma frase:** A Factory é uma **plataforma local de engenharia assistida por IA**, com memória, testes, controle de recursos e supervisão humana — projetada para ser **segura, auditável e incremental**, começando pequena e evoluindo com base em evidências reais de uso.
